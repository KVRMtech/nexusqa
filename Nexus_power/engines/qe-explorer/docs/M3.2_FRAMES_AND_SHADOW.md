# M3.2 — Cross-origin iframes and closed shadow roots

Two DOM-visibility gaps, closed. The stop condition for this milestone is that a
previously opaque surface becomes **catalogued evidence, not merely detected** —
so every claim below is stated with what measures it.

---

## 0. Re-grounding: why `enter_frames` had no effective consumer

`perception.route_opaque_surfaces()` classified a cross-origin iframe as
`enter_frames`, and nothing ever read that bucket. Two independent reasons, and
fixing either alone would not have helped:

1. **No caller.** In production the function was called from exactly one place —
   `perception.should_perceive()` — which reads only `routed["vision"]`.
   `routed["enter_frames"]` was read nowhere outside `tests/test_perception.py`.
   `discovery.py` imports `perception` and calls `should_perceive`, never
   `route_opaque_surfaces`.

2. **Nothing to consume.** `OPAQUE_JS` emitted `{kind, label, reason}`, where
   `label` was a **host** (`js.stripe.com`). A host is not something
   `page.frame_locator()` can be handed. The route was a classification with no
   handle attached, so even a caller could not have acted on it.

A third fact shaped the design: `PlaywrightBrowserPort._locator()` already
consumes `frame_selector` via `frame_locator`, so **acting** inside a frame
worked. Only **observing** inside one was missing.

For closed shadow roots the situation was simpler: `INVENTORY_JS.walk()` reads
`host.shadowRoot`, which the spec keeps `null` for `mode:"closed"`. Nothing
patched `attachShadow`, and `context.add_init_script` was used exactly once in
the whole service (sessionStorage replay). The surface was permanently opaque.

## 1. T-FR-01 — frame-scoped observation

**Where it lives.** In `PlaywrightBrowserPort.collect_controls_result()`, inside
the read that produces the observation — not beside it. Every consumer of an
observation (state fingerprint, form filler, catalogue, walker) therefore sees
frame controls without any of them being taught about frames, and a control
inside a payment iframe is evidence on exactly the same terms as one beside it.

**The sequence.**

| step | mechanism |
|---|---|
| detect | `OPAQUE_JS` finds unreadable frames and now emits an escaped, deterministic `frame_selector` for each |
| route | `perception.route_opaque_surfaces()` — the same pure function the vision escalation consults, so "which surfaces are enterable" is answered in one place |
| identify | `locator.element_handle()` → `content_frame()` → a real Playwright `Frame`; identity recorded as `scheme://host` |
| observe | `frame.evaluate(INVENTORY_JS)` — the **production** walker, inside the frame's own execution context |
| return | the chain of selectors is joined with the walker's own `" >>> "`, which `_locator()` already splits on |
| recurse | one more level (`_MAX_FRAME_DEPTH = 2`), for a 3-D-Secure step inside a payment frame |

**Origin isolation is used, not circumvented.** Nothing is injected across the
boundary. `content_frame()` asks the *browser* for the frame's execution
context; the walker then runs under that frame's origin exactly as the frame's
own scripts do. The walker's honest `contentDocument` skip is unchanged, and
`test_the_walker_itself_still_refuses_to_read_across_the_origin_boundary` pins
it — along with a check that no injected snippet contains `document.domain`,
`postMessage` or `contentWindow.eval`.

**Bounds.** 6 frames per observation, depth 2, 60 controls per frame. Every
limit is a named constant, and a clipped read says so in its ledger row.

**A defect this milestone's own fixture found.** `OPAQUE_JS` deduped its rows on
`kind|label`, and a cross-origin frame's label is its **host**. A checkout that
embeds a card frame and a 3-D-Secure frame from the same vendor is two frames on
one host, so the second was dropped before anything could enter it — named
nowhere, and indistinguishable in the ledger from a page with one embed.
Fixtures 04 and 25 embed a single frame each, so neither could see it; fixture 26
puts four on one host. The dedup key is now the frame's **selector** when it has
one, and the coverage ledger's frame rows carry the selector in their label for
the same reason (`coverage._dedup_opaque` keys on `kind|label` too).

**Evidence.** `drain_frame_evidence()` yields one row per frame met — entered
(selector, origin, control count, depth) or refused (with the reason) — drained
per-visit by `discovery.py` into the coverage ledger as `frame_entered` /
`frame_not_entered`. A crawl that read a payment frame and one that could not
address it no longer produce identical coverage.

**Secrets.** The identity is an **origin**, never a URL: a vendor frame URL
routinely carries a client secret, a session token or a payment-intent id in its
query string, and this string travels into the manifest and out to qe-central.

## 2. T-FR-02 — closed shadow roots

`CAPTURE_HOOKS_JS` is installed with `context.add_init_script` **between
`new_context()` and the first `new_page()`** (`app/main.py`). It wraps
`Element.prototype.attachShadow` and keeps a `mode:"closed"` root in a `WeakMap`
reachable only through a non-enumerable `window.__nxCaptureHooks`.

**Why there and nowhere else.** `attachShadow({mode:"closed"})` hands its root to
the component and to nobody else; no API recovers it afterwards. A retrofit
cannot work, because the root it would need was created and captured before it
arrived. `test_a_retrofitted_hook_provably_cannot_see_a_closed_root` measures
this rather than asserting it: a context with no init script sees nothing inside
the root, and installing the hook afterwards does not recover it.

**Why this is not a security bypass.** A closed shadow root is an *encapsulation
convention* — the HTML spec says so explicitly — and the DOM it hides is
same-origin, same-process content the page already rendered to the user. Nothing
here reaches another origin, process or context. Contrast T-FR-01, where the
boundary is real and injection is refused.

**The page cannot tell.** `el.shadowRoot` still reads `null` for a closed root;
the replacement is non-enumerable, carries the native `name`/`length`, and
forwards `toString` to the native implementation.
`test_the_hook_is_invisible_to_the_application` checks all of it, plus that an
open root still round-trips.

**Documented limits.**

* Declarative shadow DOM (`<template shadowrootmode="closed">`) does not go
  through `attachShadow` and is **not** observed. Such a surface stays a named
  `closed_shadow` row. Fixture 26 carries one, and
  `test_a_declarative_closed_shadow_root_stays_an_honest_blind_spot` measures it
  — so the limitation is a fact the suite holds, not a sentence in a docstring
  that someone later trusts.
* **A closed-shadow control is observable but not bindable.** Playwright's
  selector engine pierces *open* shadow roots by reading `element.shadowRoot`,
  which is `null` for a closed one — for Playwright exactly as for the page.
  There is no supported selector that reaches inside. So the control is
  catalogued (it is a real question the application asks, and omitting it is the
  blind spot this milestone closes) and **stamped** `shadow_scope:
  "closed_shadow"`, so nothing downstream can read "catalogued" as "replayable".
  `test_a_closed_shadow_control_is_catalogued_but_declared_unbindable` measures
  both halves: the flag is set, and the binding really does fail.

  A crawler-only custom selector engine (`playwright.selectors.register`) would
  make these bindable *for the crawl* and not for a generated script — the exact
  capture-says-covered / replay-cannot-bind asymmetry this engine's browser
  harness exists to catch. It was deliberately not built.

**Reported as observed, not opaque.** `OPAQUE_JS` emits `closed_shadow_entered`
(with the control count and `controls_bindable: false`) when the hook pierced the
root, and `closed_shadow` only when it is genuinely blind. Reporting a surface we
read as a blind spot understates coverage exactly as badly as the reverse
overstates it.

## 3. T-FR-03 — frame selector correctness

Escaping was already fixed (BUG-IFRAME-SELECTOR). Escaping makes a selector
*parse*; it does not make it *identify*. Two defects remained:

1. **Ambiguity.** Two iframes sharing a `title`/`name`/`src` emitted the same
   selector. `frameLocator` takes the first match and says nothing, so every
   control captured in the second was recorded against the first — the failure
   that reads as coverage. Now: the rung's value is checked for uniqueness among
   the frames its own scope can see, and disambiguated with `>> nth=<ordinal
   among its own matches>`.

2. **Page-global indexing.** `iframe >> nth=N` is resolved document-wide by
   Playwright's shadow-piercing engine, while `N` was the loop index inside
   whichever subtree the walker was standing in. Now: a frame inside a shadow
   root is addressed **through its host** (`div#shadow-host >> iframe >> nth=0`),
   which needs no cross-root ordinal at all; and the frame list is built
   breadth-first — a root's own tree before the shadow roots hanging off it —
   which is the order Playwright demonstrably resolves in.

3. **The host was only ever addressed by id.** Addressing the frame is half of
   it; a shadow-nested frame is reached through its **host**, and the host needs
   an address too. Every fixture happened to give its host an `id`, so the other
   two shapes — a host that is the only element of its tag in its root (bare
   tag), and one with same-tag siblings (`section >> nth=1`) — were never
   executed. A component library that never expected to be addressed from
   outside gives its hosts neither reliably.

One recipe (`_FRAME_SELECTOR_JS`) is now injected into **both** `INVENTORY_JS`
and `OPAQUE_JS`, because the snippet that detects a frame and the snippet that
captures inside one must name it identically.

**The port verifies rather than trusts.** Before entering, it counts the
selector's matches; anything but 1 is refused and ledgered with the count.
Refusing is the only honest answer to an ambiguous address.

Fixture **24-iframe-ambiguous-attrs** covers all three on the same-origin side,
with a title full of quotes, apostrophes and brackets so escaping and uniqueness
are exercised together. Fixture **26-opaque-surface-rungs** covers them on the
cross-origin side — the one that decides whether a frame can be entered at all —
where, before it, only the first rung had ever run.

Two branches were **removed** rather than covered: `hostSelectorFor` and
`frameRung` each had a "searched the list and did not find it" exit that is
unreachable by construction (the element being searched for is taken from the
list). `Array.prototype.indexOf` says the same thing without the dead tail. Dead
code is not neutral in a repo with a coverage ratchet — it turns the ratchet into
a measurement of scaffolding.

## 4. Evidence

| claim | where it is measured |
|---|---|
| frame discovery | `test_the_frame_ledger_records_entry_and_identity` — the `cross_origin_iframe` row carries `frame_selector` + `frame_host` |
| frame identity | same test — `origin` is `scheme://host`, asserted to carry no path or query |
| catalog records from inside the iframe | `test_a_real_crawl_of_the_proving_ground_catalogues_both_surfaces` — the payment fields are in `coverage.states[0].form_snapshot_signals`, the shape qe-central builds catalogue questions from, each keeping `locator.frame_selector` |
| closed-shadow evidence | `test_a_closed_shadow_component_exposes_its_controls`, `test_the_closed_shadow_surface_is_reported_as_observed_not_opaque`, `test_a_retrofitted_hook_provably_cannot_see_a_closed_root` |
| selector edge cases | `test_ambiguous_and_shadow_nested_frame_selectors_bind_the_right_frame` — every emitted selector is handed back to the browser and must **bind the control captured through it**, not merely resolve |
| fixture crawl | the real-crawl test above: production `Crawler`, real budget, real guard, real manifest writer |
| regression suite | `test_the_patch_does_not_break_ordinary_pages` (open / closed / nested / plain DOM), the full `tests/browser` suite, and the re-recorded characterization goldens |
| the stated limits | `test_a_declarative_closed_shadow_root_stays_an_honest_blind_spot`, `test_a_closed_shadow_control_is_catalogued_but_declared_unbindable` — both limitations are measured, so neither can quietly stop being true |

**Standard of proof.** No assertion in the M3.2 suite compares a selector
*spelling*. A selector can be beautifully escaped, resolve to exactly one frame,
and still be the wrong one — which is indistinguishable from coverage in every
report, and therefore the only failure worth testing for.

## 6. Measured cost

`collect_controls_result()` now evaluates `OPAQUE_JS` on every inventory read, so
the frame scan is paid per read rather than once per state. Measured through the
production port on Chromium:

| fixture | `INVENTORY_JS` | `OPAQUE_JS` | `collect_controls()` |
|---|---|---|---|
| 07-native-select-250 | 11.3 ms | 3.4 ms | 13.4 ms |
| 09-questionnaire-20 | 24.9 ms | 5.4 ms | 28.8 ms |
| 25-proving-ground | 10.1 ms | 3.1 ms | 38.0 ms |

On a frame-free page the addition is the scan alone (3-5 ms, against a 10-25 ms
inventory read and a 1.5 s post-action network settle). On a page with an embed
the extra ~28 ms is the entry itself — real work, and the point of the milestone.

It is deliberately **not** cached. A frame's DOM changes as the crawl acts on the
page, so a cached read would hand a later state an earlier state's controls,
which is the failure mode this engine is built to avoid.
