# Agentic Autonomous Pipeline — Video -> Test -> Playwright -> Execution (no human, grounded, never-green-wash)

Designed 2026-06-29 by a 6-agent grounded design pass (wf_e0dc9b32). Reuses existing primitives; mostly EXTEND.

## Architecture
Nexus QA today STOPS at the first low-confidence step: in compiler.py the per-step loop (L786-790) emits `test.skip(true, "UNPROVEN...")` whenever `provenance==inferred` or `confidence==review`, which skips the WHOLE Playwright test and forces a human to confirm. The fix is NOT to delete the skip but to add an Autonomous Grounded Step-Resolver (AGSR) that turns each such step into an EXECUTABLE + ASSERTED step, drives a live sandboxed browser to the proven prefix, binds the intended control via the existing grounded stack, and VERIFIES the step's already-recorded expected outcome (observed.next_url path-regex / observed.after outcome-region / grounded expected_result token â€” exactly what `_assertion_from_expected_result` already compiles). Verified-by-execution AND reproduced on the existing 2x-confirm re-run upgrades review->high (proven, not human-confirmed). Not verifiable after N bounded grounded attempts escalates: a CONTRADICTED recorded outcome (toHaveURL fails) or a 5xx (network_oracle) auto-authors a replayable defect via defect_report; otherwise an honest needs_human. AGSR is mostly an ORCHESTRATION over proven primitives â€” compile_case_with_overrides, diagnose, _capture_live_cap, agentic_heal.propose (binds only to verbatim live-a11y names, drops ungrounded picks at validate_fixes), assert_assertions_unchanged, suite_outcome_grounding, the run-id-correlated prove+confirm gate, record_heal_event (fail-closed Part-11 ledger), and the proven-control ledger. The agent only ever PROPOSES {target_name, control_kind} or {wait} from a 5-verb constrained vocabulary; the DETERMINISTIC compiler still emits the owned Playwright and the orthogonal recorded-outcome oracle decides green. A new server-side-only `autonomous_resolve=True` flag flips this on for heal sub-runs; the buyer's downloaded bundle path keeps skipping, so every existing test stays byte-identical. A constrained own-driver (NOT the open-ended Playwright MCP) plus an in-browser egress allowlist provides the secure browser control, default-off behind NEXUS_AGENTIC_BROWSER + per-tenant gate.

## Invariants (never-green-wash under autonomy)
- NEVER-GREEN-WASH-UNDER-AUTONOMY: 'proven' means the step's RECORDED outcome oracle (next_url/after/expected_result) was independently re-asserted by the deterministic compiler AND ran green twice on independent confirm re-runs AND verdict != real_regression. 'It stopped failing' is NEVER proven.
- GROUND-TRUTH-OR-REFUSE: an UNPROVEN step whose recorded outcome does NOT compile to a non-tolerant grounded assertion (step_outcome_grounded == False) is NOT autonomously upgradable â€” it escalates to needs_human. We refuse to bless an unverifiable step; we never guess.
- ORTHOGONAL ORACLE: the agent chooses WHICH control/outcome to bind; a DIFFERENT mechanism (deterministically-compiled toHaveURL/outcome assertion executed by the runner in a separate process, correlated by sub-run-id not newest-by-time) decides pass. The agent's own 'I succeeded' is never the gate.
- AGENT PROPOSES, COMPILER DISPOSES: the agent emits only {target_name, control_kind} or {wait} from a 5-verb vocabulary (click/type/select/navigate-within-app/assert). No free-form Playwright, no page.evaluate, no arbitrary JS â€” structurally absent, not policy-filtered. Output stays deterministic, owned, auditable, reproducible.
- VERBATIM-NAME GROUNDING: a proposed target_name must appear verbatim in the live a11y snapshot or validate_fixes drops it. The page DOM is DATA, never instructions â€” closes prompt-injection and fabricated-locator green-wash.
- ASSERTION-IMMUTABILITY: a resolution may ADD a grounded oracle to a previously-skipped step but may NEVER reduce grounded assertions (assert_assertions_unchanged rejects candidate with fewer). 'Weaken-the-assertion-to-go-green' is structurally impossible.
- REFUSE-FLOOR FIRST: REAL_REGRESSION / AUTH / DATA / VARIANT (diagnose REFUSE_CAUSES) and a network_oracle 5xx are evaluated BEFORE any resolution and are excluded from AGSR â€” a contradicted recorded outcome routes to an auto-authored defect, never a heal.
- BYTE-IDENTICAL DEFAULT: all new behavior is gated (autonomous_resolve=False, NEXUS_AGENTIC_BROWSER off, per-tenant opt-in). The downloaded buyer bundle and every existing test remain byte-identical; autonomy is server-side, opt-in, fail-closed.
- BOUNDED + AUDITED: max_attempts per (sid,step) + _AUTO_HEAL_MAX_ITERS + optional per-heal SLA budget; exhaustion ALWAYS terminates to needs_human + defect, never to green-or-skip-as-pass. Every autonomous upgrade/refusal/defect writes a fail-closed, hash-chained Part-11 row with actor='autonomous-agent'.
- PER-STEP BLAST-RADIUS CONTAINMENT: an upgrade fires only when THAT step's recorded outcome is proven+confirmed; newly-unblocked downstream steps keep their own oracles/skip rules, and the suite-level hollow/outcome_not_grounded rollup flags any all-green-but-hollow tail rather than freezing it.

## Keystone — Autonomous Grounded Step-Resolver (AGSR) â€” resolve_unproven_step
For an extracted step currently compiled as `test.skip(true)` because provenance==inferred or confidence==review, AGSR removes the human: it reaches the proven-prefix state in a live sandboxed browser, binds the intended control via the existing grounded stack, performs the recorded action through the deterministic compiler's constrained kind-aware verbs, and VERIFIES the step's ALREADY-RECORDED expected outcome (observed.next_url path-regex / observed.after outcome-region / grounded expected_result token) actually occurred. Verified AND reproduced on an independent 2x-confirm re-run upgrades the step review->high (proven by execution, not by a human and not by the agent's say-so). Not groundable, contradicted, or exhausted => escalate / auto-author a defect. The agent only ever PROPOSES {target_name, control_kind} or {wait}; the deterministic compiler emits the owned Playwright and the orthogonal recorded-outcome oracle decides green.

### How it cannot fake a pass
Five structural, not policy, barriers â€” every one already exists and is reused: (1) GROUND-TRUTH-OR-REFUSE â€” step 2 refuses to upgrade any step whose recorded outcome does not compile to a non-tolerant grounded assertion (step_outcome_grounded==False); there is literally no green path for an unverifiable step. (2) ORTHOGONAL ORACLE â€” the agent picks WHICH control to bind; the deterministic compiler emits `_assertion_from_expected_result` (toHaveURL(next_url)/outcome-region/grounded token) and the Playwright runner in a separate process, correlated by sub-run-id not newest-by-time, decides pass â€” the agent's 'I succeeded' is never read. (3) VERBATIM GROUNDING â€” validate_fixes drops any target_name not present verbatim in the live a11y snapshot, so a fabricated/plausible-but-wrong locator cannot be bound; and a wrong bind that reaches the wrong page FAILS toHaveURL RED. (4) ASSERTION-IMMUTABILITY â€” assert_assertions_unchanged rejects any candidate with fewer grounded assertions, making 'weaken the oracle to go green' impossible; the tolerant not.toHaveValue('') check is excluded from grounded counting so 'a value committed' can never masquerade as outcome proof. (5) REFUSE-FLOOR + 2x-CONFIRM â€” REAL_REGRESSION/AUTH/DATA/VARIANT and a network_oracle 5xx are excluded BEFORE any attempt and route to an auto-authored defect; a contradicted recorded outcome stays RED; and a single green is never enough â€” the same candidate must reproduce green on an independent confirm run with verdict != real_regression. Exhaustion ALWAYS terminates to needs_human + defect, and every decision is a fail-closed hash-chained Part-11 row with actor='autonomous-agent'.

## Secure browser-control / MCP toggle
Build our OWN constrained driver, do NOT wrap the official Playwright MCP server: MCP's value is exactly its danger â€” an open-ended browser tool surface including page.evaluate/arbitrary JS handed to an LLM, page-content-as-instructions prompt injection, and unconstrained egress â€” a surface that grows every release and that we would have to police forever. The owned ConstrainedAgentDriver (new /agent-step in infrastructure/runner/server.js) exposes only a 5-verb enum (click/type/select/navigate-within-app/assert) chosen BY NAME from the live a11y snapshot, with NO evaluate/JS sink â€” arbitrary JS is structurally absent, not policy-filtered, so prompt injection has nothing to inject into and the agent can never read storageState. An in-browser context.route egress lock allows ONLY {app origin(s) derived from base_url, NEXUS_ENDPOINT} and aborts everything else (META_IP stays hard-blocked), closing data-exfiltration/SSRF regardless of what the model proposes; navigate-within-app is path-relative to base_url so there is no mid-flow cross-origin goto. Auth is storageState-only, decrypted briefly and wipeAuth()'d after each ephemeral run. The whole capability is fail-closed behind NEXUS_AGENTIC_BROWSER (default off) AND a per-tenant opt-in via agentic_browser_gate.is_enabled, layered on the existing enable_agentic_heal/agentic_tier/agentic_min_confidence ctx â€” off means AGSR no-ops and steps skip exactly as today, byte-identical. Every agent action writes a tamper-evident hash-chained audit line so the full autonomous session is replayable.

## Open questions (founder decisions)
- Upgrade durability: when AGSR proves an UNPROVEN step review->high, does the customer's NEXT downloaded bundle now EMIT that step as real Playwright (no longer skipped), or does the buyer bundle stay byte-identical-skip until a human ratifies? Proposed default: server upgrades the stored ProductionTestCase so the next compile emits it, with a visible 'autonomously proven (actor=agent), not human-ratified' provenance badge â€” confirm this is acceptable for regulated buyers vs. requiring a human sign-off before the bundle changes.
- Region-only outcome strength: many recorded steps have observed.after (outcome region) but NO observed.next_url (SPA same-URL transitions). The current rule treats region-only as needs_human (not auto-upgradable). Is that too conservative â€” should a strong observed.after + a grounded expected_result token jointly qualify as proven for SPA flows, or do we hold the line and require next_url?
- Per-tenant cost ceiling: autonomous driving + LLM proposal per UNPROVEN step has real $ cost. What is the default max_attempts (proposed 3) and SLA budget per tenant, and should AGSR be opt-in per-RUN (surface-toggle pattern) so a customer explicitly pays for autonomy, or on-by-default once NEXUS_AGENTIC_BROWSER is set?
- Defect vs. needs_human threshold: on exhaustion with a NON-contradicted outcome (locator simply never resolved), we escalate needs_human without a defect. Should an unresolvable control after N grounded attempts ALSO auto-author a (lower-severity) defect so the customer always gets an actionable artifact, or keep defects reserved for contradicted-outcome/5xx real-bug signals only?
- Egress allowlist breadth: real apps legitimately call N first-party + CDN + auth origins. Do we derive the allowlist purely from base_url + NEXUS_ENDPOINT (strict, may break apps with separate API/auth origins) or let the tenant declare an allowlist in surface_prefs? Strict-by-default with tenant-declared additions is proposed â€” confirm.
- Audit actor trust + signing key custody: record_heal_event(actor='autonomous-agent') is server-set and the row is hash-chained; do we need an asymmetric signature (sign_row_hash) with a key the app DB role lacks for the autonomous-upgrade rows specifically (since no human is in the loop), and where does that key live on the new GCP?

The research consensus is unambiguous: what makes an autonomous GUI agent reliable rather than hallucinatory is NOT smarter planning but tighter GROUNDING and an explicit per-action VERIFICATION LOOP â€” act, then observe the real page, then verify the achieved state against the known goal-state before proceeding (SeeAct: "GPT-4V is a generalist web agent, IF grounded"; ReflAct/ORCA goal-state reflection; WebVoyager's GPT-4V trajectory verifier at 85.3% human agreement).
